- 2026-10-05 — **Correction** to the "Issues for the clean step" entry above: the corpus has *no* U+FFFD. The `µ` was stored correctly, and `�` was just the Windows console failing to display it. The real issue is about 1,800 Private Use Area chars (U+F0xx) from Symbol/Wingdings fonts. `clean.py` maps the ones seen here (U+F06D→µ, F0B3→≥, F0A3→≤, F0B0→°, bullets→•), drops any other PUA char, and unifies Greek μ→µ before `g/m`/`m`. Lesson: check code points (`unicodedata.name`), not terminal output.
- 2026-10-05 — Clean step writes `data/processed/clean/<doc_id>.jsonl` and never modifies the parse output — clean in place — re-cleaning is instant while re-parsing (OCR) takes minutes. Boilerplate = short (≤ 200 chars) non-table block whose digit-normalised text appears on ≥ max(2, 50%) of pages, plus page-number-only blocks; removes about 1,500 blocks corpus-wide. Merged-cell dedupe only blanks *text* cells equal to their left neighbour, because equal adjacent numbers are real values (NAAQS SO2 24 h: 80 | 80). This caught a data-loss bug in the first version.
